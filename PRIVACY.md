# Политика конфиденциальности

Whois Watcher — бесплатный сервис с открытым исходным кодом. Этот документ
описывает, какие данные собираются и как с ними обращаются.

«Мы» далее — оператор конкретного экземпляра бота. Проект открытый, и
каждый может развернуть свой инстанс — если вы пользуетесь публичным,
данные хранятся у его оператора. Этот документ описывает поведение
эталонной реализации; форкам ничто не мешает изменить любое из правил
ниже, проверяйте PRIVACY.md соответствующего экземпляра.

## Какие данные собираются

### От Telegram

- **Telegram ID** — обязательно, для идентификации
- **Username** — если установлен, для удобства показа в логах админу
- **Language code** — для определения языка интерфейса по умолчанию

Мы **не сохраняем**: имя, фамилию, телефон, фото профиля и иные поля
профиля Telegram.

### От вас при использовании

- **Список доменов**, которые вы добавили на слежение
- **Личные заметки** к доменам (если вы их пишете через будущий UI)
- **Настройки**: язык, часовой пояс, время и дни рассылки напоминаний
- **Тайминг команд** для расчёта rate limit (счётчики в Redis с TTL)

### Системные данные

- **Журнал отправленных уведомлений** для дедупликации (`sent_notifications`)
- **Лог системных событий** (`system_events`) — для отладки и алертов;
  хранится до 30 дней, потом чистится cron-задачей
- **WHOIS-кэш** доменов — общий на всех пользователей, не привязан к вам

## Какие данные мы НЕ собираем

- Никаких платёжных данных (сервис бесплатный, тарифов нет)
- Никакого содержимого сообщений вне команд боту
- Никаких данных из других чатов
- Никакой телеметрии устройства, IP-адресов клиента, User-Agent

## Где хранятся данные

В базе данных PostgreSQL на сервере, где развёрнут конкретный экземпляр
бота. Доступ к БД — только локальный, не наружу.

## Сколько хранятся данные

- **Профиль и домены** — пока вы пользуетесь ботом
- **Журнал отправленных уведомлений** — пока существует профиль (нужен
  для дедупликации напоминаний после продлений домена)
- **Лог системных событий** — до 30 дней (`cleanup_old_events` cron)
- **WHOIS-кэш** — общий, не привязан к пользователю; сиротские записи
  без подписчиков чистятся `cleanup_orphan_cache`

## Как удалить данные

Команда `/delete_me` с подтверждением через `/delete_me_confirm` удаляет:

- ваш профиль
- все ваши домены и подписки
- историю ваших уведомлений
- все ваши настройки

Удаление **необратимо**, не требует обращения к админам, выполняется
немедленно через `DELETE FROM users WHERE id = ?` (CASCADE удаляет всё
связанное).

Общий WHOIS-кэш не содержит привязки к вам и удалению по запросу
пользователя не подлежит — это публичные данные доменов.

## С кем мы делимся данными

**Ни с кем.** Данные не передаются третьим лицам, не продаются, не
используются для рекламы.

Исключения:

- При WHOIS-запросах к серверам регистраторов мы передаём **только сам
  домен**, без привязки к вашему ID
- Если того прямо требует закон

## Сторонние сервисы

- **Telegram Bot API** — мы общаемся с вами через webhook. См.
  [политику Telegram](https://telegram.org/privacy)
- **WHOIS / RDAP-серверы регистраторов** — туда уходит имя домена, ничего
  больше
- **Sentry** (если оператор его настроил, `SENTRY_DSN`) — может получать
  трейсбеки неперехваченных исключений. В этих событиях:
  - `send_default_pii=False` — username/IP не передаются
  - Все ключи с подстроками `token`, `password`, `secret`, `authorization`,
    `api_key`, `apikey`, `x-telegram-bot-api-secret` маскируются как
    `[Filtered]` в `before_send`
  - Полные WHOIS-ответы (`raw_data`, `raw_response`, `raw_text`,
    `raw_whois`) маскируются как `[Filtered: bulk]`
  - В трейсбеках может появиться ваш `user_id` (внутренний ID из БД) и
    `telegram_id` — этого достаточно для отладки, но без других PII
- **Админский Telegram-канал** (если оператор настроил `ADMIN_CHANNEL_ID`)
  — туда уходят технические алерты с дедупликацией. Ваш `telegram_id`
  может попасть в `#critical`-алерт, если ошибка относится к вашему
  запросу; имена доменов, добавляемых пользователями, в алерты не
  публикуются

## Безопасность

- Все секреты (`BOT_TOKEN`, `WEBHOOK_SECRET` и т. п.) хранятся в
  переменных окружения и не попадают в код, логи или Sentry
- Webhook верифицируется через `X-Telegram-Bot-Api-Secret-Token`
- Соединение с Telegram — только HTTPS (через Nginx с Let's Encrypt)
- БД и Redis не доступны извне — только внутри Docker-сети

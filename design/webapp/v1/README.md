# Handoff: Whois Watcher — Telegram WebApp

## Overview
**Whois Watcher** — Telegram WebApp (мини-приложение внутри Telegram) для мониторинга портфеля
доменов. Пользователь добавляет домены на слежение, а бот/бэкенд периодически проверяет WHOIS,
SSL-сертификаты, DNS-записи, email-защиту (SPF/DKIM/DMARC) и поддомены, и присылает уведомления
о приближении срока истечения регистрации, проблемах и изменениях.

Целевой пользователь — администратор/владелец, который ведёт десятки–тысячи доменов (свои и
клиентские) и хочет ничего не пропустить: продления, истёкшие SSL, смену NS/регистратора,
«wishlist» занятых доменов, которые он хочет поймать при освобождении.

Язык интерфейса — **русский**. Все строки, форматы дат (`26.05.2026`), денег (`1 090 ₽`) и
склонения числительных — по русским правилам.

## About the Design Files
Файлы в этом пакете (`design/app/`) — это **дизайн-референс, собранный на HTML + React (через
Babel-in-browser)**. Это рабочий прототип, который показывает целевой внешний вид и поведение, **а
не продакшн-код для прямого копирования**. Прототип намеренно завёрнут в «рамку телефона» и iOS
статус-бар, чтобы было видно, как webapp выглядит внутри Telegram на мобильном.

Задача исполнителя — **воссоздать эти экраны в реальной кодовой базе**, используя её стек и принятые
паттерны. Если кодовой базы ещё нет — выбрать подходящий стек под Telegram WebApp (например,
React/Vite + `@telegram-apps/sdk` или `window.Telegram.WebApp`) и реализовать дизайн там.

Что **не** нужно тащить в прод как есть:
- `unpkg.com` + Babel-standalone (только для прототипа; в проде — нормальная сборка);
- «рамку телефона» (`.tg-phone`, `.tg-viewport`, `.tg-statusbar`) — в реальном webapp вьюпорт даёт
  сам Telegram, рамка не нужна;
- сид-данные из `data.js` — заменить на реальные ответы API.

Что **нужно** перенести точь-в-точь: визуальный язык (цвета, типографика, отступы, радиусы),
компоновку экранов, иконографику (Material Symbols Rounded), копирайт и тон, поведение навигации.

## Design System
Прототип построен на дизайн-системе **PIN Voice** (calm, dense business-software):
- Шрифт **PT Sans** (400/700), иконки **Material Symbols Rounded**.
- Акцент — вермильон-красный `#e6403a`; основное действие (CTA) — небесно-голубой `#36a9e1`;
  positive — зелёный `#29b473`; warn — золотой `#f4b921`.
- Поверхности нейтрально-холодные, бордеры 1px, радиусы 6–8px (модалки/карточки 12px).
- Полноценная тёмная тема через `[data-theme="dark"]`.

Токены лежат в `design/app/ds/colors_and_type.css` (полный список переменных) и
`design/app/ds/styles.css` (компоненты: `.pv-btn`, `.pv-toggle`, `.pv-avatar`, бейджи и т.д.).
Мобильные паттерны Telegram-webapp поверх PIN Voice — в `design/app/tg.css`.

### 2. Карточка домена (`screen-domain.jsx`, стек `domain`)
- **Назначение**: вся информация по одному домену + управление уведомлениями.
- **Раскладка**: липкий ряд вкладок (`.tg-ctabs`, горизонтальный скролл): Обзор · WHOIS · SSL ·
  DNS · Email · Поддомены. Активная вкладка — нижняя 2px полоса `--pv-accent`. У вкладок SSL/Email
  есть цветная точка-индикатор проблемы; у «Поддомены» — счётчик.
- **Вкладка Обзор**: hero-карточка с health-ring (`Ring`, 72px) + статус-пилюлей и текстом «через N
  дней»; ряд тегов-групп; 3 быстрых действия (`QuickAct`: Обновить / Полный WHOIS / Поделиться);
  карточка «Из чего складывается health-score» (5 факторов: срок, SSL, DMARC, DNSSEC, статусы — с
  иконкой ok/warn/cancel); карточка «Уведомления» (4 тоггла `.pv-toggle`); «Лента изменений».
- **WHOIS**: срок действия (зарегистрирован/истекает/обновлён), регистратор+сайт, статусы домена

- **SSL**: hero с иконкой замка (цвет = состояние) и оценкой (A+/A/B); карточка сертификата

- **DNS**: A/AAAA записи (моно), инфраструктура (провайдер NS, ASN+организация, DNSSEC через

- **Email**: MX-провайдер; защита от спуфинга (SPF/DKIM/DMARC через `Check`); подсказка настроить

- **Поддомены**: сводка (найдено через crt.sh, N поддоменов) + кнопка «следить за всеми»; список
  поддоменов (моно), бейджи «новый»/«слежу» или кнопка «Следить».
- **Меню домена** (`more_vert` → sheet): Обновить данные, Полный WHOIS-ответ (raw, `<pre>` моно),

## Interactions & Behavior
- **Навигация**: вкладки переключают корневой экран; `push(screen)` добавляет экран в стек (скрывает
  таб-бар, показывает «назад»), `back()` снимает верхний. Смена вкладки/пуш сбрасывает скролл тела
  наверх. В реальном webapp кнопку «назад» лучше повесить на `Telegram.WebApp.BackButton`.
- **MainButton**: контекстная нижняя кнопка. Состояния: «Добавить на слежение» (disabled пока домен
  не прошёл regex-валидацию), «Импортировать 214 доменов» (green), «Сохранить» (настройки),
  «Действия · N» (массовый режим). Маппить на `Telegram.WebApp.MainButton`.
- **Bottom sheet**: маска `rgba(0,0,0,0.4)` + анимация `tgUp` (translateY 100%→0, 0.26s
  cubic-bezier(.2,.8,.2,1)); закрытие по тапу на маску. Есть «грабитель» (`.tg-sheet-grab`).
- **Toast**: показ на 2.2с, анимация `tgUp` 0.2s. Очередь не нужна — новый затирает старый.
- **Поиск**: фильтрация по имени домена и регистратору (debounce не требуется на текущем объёме, но в
  проде на 50k — нужен).
- **Мультивыбор**: тап-чек, выбранные подсвечены, действия через sheet, после действия — выход из
  режима + toast.
- **Тогглы уведомлений** (карточка домена): мгновенно меняют состояние домена + toast.
- **Тема**: тоггл переключает `data-theme` на `<html>` (light/dark). В реальном webapp —
  синхронизировать с `Telegram.WebApp.colorScheme`.
- **Анимации**: быстрые, 120–260ms, easing `ease` / один cubic-bezier для sheet. Health-ring
  анимирует `stroke-dashoffset` 0.6s. Без бесконечных декоративных лупов.

## State Management
Всё состояние — локальный React-стейт в `App` (`app.jsx`):
- `theme` — 'light' | 'dark' (пишется в `data-theme` на `<html>`).
- `domains` — массив доменов (мутируется: тоггл уведомлений, удаление, массовые действия).
- `alerts` — лента (мутируется: пометить прочитанными).
- `tab` — активная вкладка; `stack` — массив пушнутых экранов `{type, id?}`.
- `sheet` — текущий bottom sheet `{type}` или null.
- `toastMsg` — `{msg, icon}` или null.
- `st` — состояние списка: `{query, filter, sort, groupBy, selMode, sel:Set, groupView}`.
- `addVal`/`addGroup` — черновик добавления домена.

В реальном приложении: домены/алерты/настройки приходят из API, мутации → оптимистичный апдейт +
запрос на бэкенд. `sel` (Set выбранных id) удобно оставить локальным.

## Data fetching (бэкенд)
Прототип использует сид-данные (`data.js`, детерминированный seeded-RNG, 300 доменов + 60 алертов).
Реальные источники, которые подразумевает дизайн:
- **WHOIS** — даты регистрации/истечения/обновления, регистратор, статусы (EPP-флаги).
- **SSL** — издатель, срок, протокол TLS, оценка.
- **DNS** — A/AAAA, NS, провайдер, ASN, DNSSEC.
- **Email** — MX, SPF, DKIM, DMARC-политика.
- **Поддомены** — через CT-логи (crt.sh).
- **Health-score** — вычисляется из перечисленного (формула в `data.js`, см. блок `let health=100…`).
- **Уведомления** — крон-проверки по расписанию; пуши в Telegram-чат бота.

## Структура объекта домена (модель данных)
```js
{
  id, name, unicode, noData, isWishlist,
  registered, expires, updated,        // строки "ДД.ММ.ГГГГ"
  daysLeft,                            // число (может быть отрицательным) или null
  registrar, registrarHost,
  flags: [...],                        // EPP-статусы
  ssl: { issuer, validTo, daysLeft, grade, tls } | null,
  dns: { a:[], aaaa:[], ns:[], provider, asn, asnOrg, dnssec } | null,
  email: { mx, hasMX, spf, dkim, dmarc } | null,   // dmarc: 'none'|'quarantine'|'reject'|null
  subCount,
  groups: [groupId...],
  health,                              // 0..100
  notify: { expiry, ns, registrar, status },
  cost,                                // ₽/год
  addedAt, lastCheck,
}
```
Статус домена выводится функцией `statusOf(d)` (`core.jsx`): wishlist → fiolet; нет данных → gray;
<0 дн → «Истёк» red; <7 → «Критично» red; <30 → «Скоро» gold; иначе «В норме» green.

- Размеры: 11/12/13/14/15/16/18/20/24/26/28/30/32/36px. Body 13–14px. KPI-значения 26–30px.
  Заголовки экранов 16px (мобайл). Hero-числа карточки домена 22px.
- UPPERCASE-лейблы (`.tg-card-title`, `.tg-list-head`, `.tg-section-label`, `.tg-kpi-lbl`):
  11–12px, `font-weight:700`, `letter-spacing:0.05–0.06em`.
- Числа везде — `font-variant-numeric: tabular-nums`.

### Радиусы
2px (kbd) · 4px (код, menu-row) · 6px (кнопки/инпуты PIN) · 8px (карточки PIN) · 10px (поиск/sheet
поля) · 11px (`.tg-puck`, `.tg-alert-ico`) · 12px (мобильные карточки `.tg-card`, MainButton) ·
14–16px (drop-зона, FAB) · 18px (верх bottom sheet) · 99px (пилюли/бейджи/прогресс) · 50% (чек-кружок).

### Отступы (4px-база)
`--pv-s-2…64`: 2/4/6/8/10/12/14/16/20/24/32/40/48/64px. Паддинг тела экрана `.tg-pad` = 14px;
`.tg-pad-b` = 96px снизу (под таб-бар/MainButton). Зазор между карточками 12px.

### Тени
`--pv-shadow-sm/-shadow/-shadow-lg` (drop + 1px tinted outline); `--pv-focus` — синее кольцо
`0 0 0 3px rgba(54,169,225,.28)`. Карточки в статике — 1px бордер, без тени; тени только у оверлеев
(sheet/toast/FAB).

### Высоты chrome
Статус-бар 44px · Telegram-шапка 52px · MainButton 50px · FAB 52px · таб-иконки 24px.

- **Шрифт PT Sans** — тоже Google Fonts через `@import`. Для офлайн/суверенного деплоя — положить
  локальный TTF.

## Рекомендации по реализации (Telegram WebApp)
- Стек: React + Vite (или Next в SPA-режиме), `@telegram-apps/sdk` либо `window.Telegram.WebApp`.
- Перенести CSS-токены `ds/colors_and_type.css` и нужные классы из `styles.css`/`tg.css` в проект
  (как CSS-переменные / CSS-модули / Tailwind-конфиг — на ваш выбор), сохранив **значения**.
- Нативные элементы Telegram: `MainButton`, `BackButton`, `HapticFeedback`, `colorScheme`,
  `themeParams`, `expand()`, безопасные зоны (`viewportStableHeight`, `safe-area-inset-bottom`).
- Тёмную тему синхронизировать с темой Telegram.
- Объём данных (до 50 000 доменов) → виртуализация списка, серверная пагинация/поиск/фильтры.

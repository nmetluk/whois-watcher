# Спецификация команд бота

Все тексты — через локали (`src/locales/ru.py`, `src/locales/en.py`). Эмодзи как индикаторы статусов, тон умеренный.

## Список команд для BotFather

```
start - Начать работу
whois - Проверить домен
add - Добавить домен на слежение
rmv - Удалить домен
list - Список ваших доменов
csv - Экспорт в CSV
download - Импорт из файла
notify - Включить уведомления
unnotify - Выключить уведомления
settings - Настройки
stats - Статистика
check - Принудительная проверка
help - Справка
delete_me - Удалить все мои данные
```

Команда `/cancel` — есть, но в меню BotFather не выводится.
Команда `/delete_me_confirm` — внутренняя, в меню не выводится.

## /start

**Поведение:**
- Если пользователя нет в `users` — создать запись:
  - `language` определяется по `language_code` из апдейта (`ru`, `uk`, `be`, `kk` → `ru`, иначе `en`)
  - `timezone = 'Europe/Moscow'` (UTC+3)
  - `notify_days = {30, 7, 1}`
  - `notify_at_hour = 9`
- Если есть — обновить `last_active_at`

**Ответ:**
```
👋 Привет! Я слежу за вашими доменами и напоминаю об истечении регистрации.

🔧 Что я умею:
/whois <домен> — проверить WHOIS
/add <домен> — добавить на слежение
/list — список ваших доменов
/csv — экспорт в CSV
/download — массовый импорт
/settings — настройки
/help — полная справка

💡 Можно просто прислать мне домен — покажу WHOIS.

🆓 Сервис полностью бесплатный.
```

**Inline-кнопки:** `🌐 Проверить домен` `📋 Мои домены` `⚙️ Настройки`

## /whois <domain>

**Без аргумента:** ошибка `❌ Укажите домен. Пример: /whois example.com`

**Логика:**
1. Валидация и нормализация (IDN → punycode)
2. Проверка `whois_cache`:
   - Если запись есть и `fetched_at` свежий по адаптивному TTL — отдать из кэша
   - Если нет или устарела — синхронный запрос RDAP/WHOIS (с таймаутом)
3. Сохранить/обновить в `whois_cache`

**Ответ для зарегистрированного домена:**
```
🌐 example.com

📅 Срок действия
├ Зарегистрирован: 15.03.2010
├ Истекает: 15.03.2027 (через 318 дней)
└ Обновлён: 15.03.2026

🏢 Регистратор: RU-CENTER (nic.ru)

🔧 Статусы:
├ clientTransferProhibited
└ clientUpdateProhibited

🌍 NS-серверы:
├ ns1.nic.ru
└ ns2.nic.ru

ℹ️ Данные получены: только что
```

**Inline-кнопки:**
- Если домена нет в `user_domains` пользователя → `👁 Следить`
- Если есть → `🗑 Снять со слежения`
- Всегда → `🔄 Обновить` `📄 Полный ответ`

**Кнопка "🔄 Обновить":** force-refresh, rate limit `FORCE_REFRESH_COOLDOWN_HOURS` на пару (user, domain).

**Кнопка "📄 Полный ответ":** показать `raw_data` в `<pre>`-блоке, если умещается в одно сообщение; иначе отправить как файл `.txt`.

**Ответ для свободного домена:**
```
🌐 example.com — не зарегистрирован

Домен свободен для регистрации.
```

**Inline-кнопки для свободного:**
- `👁 Уведомить о появлении` (закомментировано в коде, фича для будущей версии — кнопка «Зарегистрировать» тоже закомментирована)

**Edge cases:**
- Невалидный домен → `❌ Не похоже на домен. Пример: example.com`
- WHOIS не отвечает, но в кэше есть старые данные → показать с пометкой `⚠️ Данные могут быть устаревшими (последнее обновление N дней назад)`
- WHOIS не отвечает и кэша нет → `❌ Не удалось получить данные. Попробуйте позже.`
- Несколько доменов в одном сообщении (без команды): WHOIS для первого + подсказка использовать `/download` если их много

## /add <domain>

Только один домен за раз.

**Без аргумента:** ошибка с примером.

**Логика:**
1. Валидация и нормализация (IDN → punycode)
2. Проверка лимита `MAX_DOMAINS_PER_USER` (50_000)
3. Проверка дубля — если уже в `user_domains`, ответить с текущими данными, не считать ошибкой
4. INSERT в `user_domains`
5. Проверить `whois_cache`:
   - Если есть и `expires_at` известен — сразу ответить с датой
   - Если нет — INSERT `whois_cache` с `next_check_at = now()`, enqueue `check_domain`, ответить "Проверяю..."
6. Когда воркер завершит — отправить отдельное сообщение с данными

**Ответ (успех с известными данными):**
```
✅ example.com добавлен на слежение

📅 Истекает: 15.03.2027 (через 318 дней)
🏢 Регистратор: RU-CENTER
🔔 Уведомлю за 30, 7 и 1 день
```

**Inline-кнопки:** `⚙️ Настроить уведомления` `🗑 Удалить`

**Ответ (данные подгружаются):**
```
✅ example.com добавлен на слежение

Подгружаю WHOIS-данные, пришлю результат через минуту.
```

**Edge cases:**
- Достигнут лимит → `❌ Достигнут лимит {MAX_DOMAINS_PER_USER} доменов. Удалите ненужные через /rmv или /list.`
- Лимит `/add` в час → `❌ Слишком много запросов. Попробуйте через X минут или используйте /download.`
- WHOIS показал, что домен свободен → добавить можно (на случай, если пользователь хочет ловить момент регистрации), но предупредить

## /rmv <domain>

**Без аргумента:** ошибка с примером.

**Логика:**
1. Нормализовать (IDN → punycode)
2. DELETE из `user_domains` где `user_id = ? AND domain = ?`
3. Запись в `whois_cache` **не трогать** — её могут смотреть другие. Сборщик мусора удалит, если никто не подписан

**Ответ:**
- Успех: `🗑 example.com удалён из вашего списка`
- Не было в списке: `❌ Этот домен не отслеживается`

При удалении из `/list` через кнопку — подтверждение `Вы уверены? [Да] [Отмена]`.

## /list

**Логика:**
1. SELECT с JOIN `user_domains` × `whois_cache`
2. Сортировка по `expires_at ASC NULLS LAST`
3. Пагинация 50 записей на страницу

**Формат записи:**
```
{статус-эмодзи} {domain} — через N дней (DD.MM.YYYY) {🔕 если уведомления off}
```

**Статус-эмодзи:**
- 🟢 > 30 дней
- 🟡 7–30 дней
- 🔴 < 7 дней или истёк
- ⚫ нет данных
- 🔕 (доп.) если выключены все уведомления

**Заголовок:**
```
📋 Ваши домены ({total})

Страница {n}/{total_pages}
```

**Inline-кнопки внизу:**
- `◀️ Назад` `Вперёд ▶️` (если есть страницы)
- `🔍 Поиск` — открыть FSM-ввод подстроки (см. ниже)
- `🔍 Фильтр`
- `📥 CSV`

**Фильтры (после нажатия 🔍 Фильтр):**
- `Все`
- `Истекающие (< 30 дней)`
- `🚨 С проблемами` — есть critical-статусы (clientHold / pendingDelete / …)
- `💀 Истёкшие` — `expires_at < now()`
- `Без данных`
- `Без уведомлений`
- `🎯 Wishlist` — режим «жду освобождения», см. `/wishlist`

**Поиск (Этап 9):**
1. Нажатие `🔍 Поиск` переводит в FSM `ListSearchStates.waiting_for_query`.
2. Пользователь вводит подстроку (можно `пример` — найдёт и `xn--…`-форму),
   либо `/cancel` для выхода.
3. Подстрока сохраняется в Redis `list_state:{user_id}` (TTL 30 мин) вместе
   с активным фильтром — пагинация prev/next теперь корректно сохраняет
   и поиск, и фильтр (раньше любое prev/next сбрасывало фильтр в "all").
4. В заголовке появляется строка `🔍 Поиск: <query>`; кнопка `🔍 Поиск`
   заменяется на `❌ Сбросить поиск`.
5. `/list` команда без аргументов СБРАСЫВАЕТ search/filter — это «начать заново».

**Пустой список:** `У вас пока нет доменов. Используйте /add чтобы добавить.`
**Пустой поиск:** `По запросу <query> ничего не найдено.`

## /csv

**Логика:**
1. Если у пользователя 0 доменов — `У вас нет доменов для экспорта`
2. Если > 10_000 — отправить ответ "Готовлю файл...", запустить генерацию в фоне
3. Иначе — генерировать сразу
4. Отправить как документ `domains_YYYY-MM-DD.csv`

**Формат:**
- UTF-8 with BOM
- Заголовки: `domain,expires_at,days_left,registrar,status,notifications,added_at,note`
- `domain` — в Unicode-форме (декодируем из punycode для удобства пользователя)
- `notifications` — `on` / `off` (если все три типа выключены — `off`)

## /download

**FSM-команда.**

**Шаг 1.** Пользователь вводит `/download`. Активируем состояние `waiting_for_file`.

```
📥 Импорт доменов

Пришлите файл TXT или CSV со списком доменов
(по одному на строку или в первой колонке).

Лимит: {MAX_DOMAINS_PER_DOWNLOAD} доменов за раз.

[❌ Отмена]
```

**Шаг 2.** Ожидаем `Message.document` от этого пользователя.

- Таймаут состояния: `DOWNLOAD_STATE_TIMEOUT_MINUTES` (5)
- Лимит размера файла: 5 МБ (≈ 100K строк)
- Если приходит не файл — `Пришлите файл или /cancel`

**Шаг 3.** Парсинг и валидация:
- Прочитать построчно (или первую колонку CSV)
- Очистить от пробелов, протоколов, путей
- Валидировать через `validators.is_valid_domain`
- Нормализовать в punycode
- Дедуплицировать в пределах файла
- Проверить, какие уже отслеживаются

**Превью:**
```
📋 Найдено {N} доменов

✅ Валидных и новых: {new}
⚠️ Уже отслеживается: {already}
❌ Невалидных: {invalid}

Примеры:
• example.com
• mysite.org
• shop.ru
... и ещё {rest}

[✅ Добавить {new}] [❌ Отмена]
```

Если есть невалидные — кнопка `📄 Показать невалидные` (отправить файлом).

**Шаг 4.** При подтверждении:
1. Проверить лимит `MAX_DOMAINS_PER_USER` суммарно (текущее + добавляемое)
2. Если превышен — отказ
3. Batch INSERT в `user_domains`
4. Batch INSERT в `whois_cache` (только новые), `next_check_at = now()`
5. Поставить в очередь проверки порциями (не все 5000 в одну секунду — распределить по `MAX_CONCURRENT_WHOIS`)
6. Прогресс-сообщение, обновляемое каждые 5-10 сек

**Финал:**
```
✅ Добавлено {N} доменов.
Данные подгружаются в фоне, проверьте /list через несколько минут.
```

**Edge cases:**
- Не текстовый файл / не парсится → `❌ Не удалось разобрать файл.`
- Лимит `/download` в сутки превышен → отказ с указанием когда можно
- Лимит размера → отказ
- Превышен лимит доменов на пользователя → добавить столько, сколько влезет, сообщить остаток

## /notify <domain> и /unnotify <domain>

**Вариант A:** одна команда — вкл/выкл всех уведомлений для домена.

`/unnotify` выключает: `notify_expiry`, `notify_ns_change`, `notify_registrar_change`, `notify_status_change`.

`/notify` возвращает дефолтные значения: expiry=true, ns=false, registrar=true, status=true.

**Без аргумента:** ошибка
```
❌ Укажите домен. Пример: /unnotify example.com
Чтобы посмотреть домены: /list
```

**Ответ /unnotify:**
```
🔕 Уведомления для example.com выключены
Домен остаётся в списке, напоминаний не будет.
```
Inline: `🔔 Включить обратно`

**Ответ /notify:**
```
🔔 Уведомления для example.com включены
Напомню за 30, 7 и 1 день до истечения.
```

**Edge cases:**
- Домена нет у пользователя → `❌ Этот домен не отслеживается`

Гранулярная настройка (типы уведомлений по отдельности) — через `/settings` → выбор домена → меню переключателей. На MVP можно отложить.

## /wishlist `[domain]` (Этап 9)

Wishlist — отдельный режим: пользователь добавляет занятый домен и получает
**одноразовое** уведомление, когда домен освободится.

**Без аргумента:** показать текущий wishlist (как `/list` с фильтром wishlist).

**С аргументом:** `/wishlist example.com`
1. Нормализуем (idn → punycode).
2. Проверяем общий лимит `MAX_DOMAINS_PER_USER` (одна квота на tracking + wishlist).
3. UPSERT в `user_domains`: ставим `is_wishlist=True` + выключаем все `notify_*`
   флаги — wishlist'еру нужны только wishlist-уведомления.
4. Если домена нет в `whois_cache` — заводим запись и ставим первичную проверку.
5. Ответ: `🎯 example.com добавлен в wishlist. Пришлю одно уведомление, когда домен освободится.`

**Inline-кнопка** `🎯 Хочу когда освободится` в карточке `/whois` — shortcut к
тому же действию.

**Жизненный цикл wishlist-домена:**
- Plan-driven `check_domain` идёт каждые 24 часа (см. `calculate_next_check(is_wishlist=True)`)
- Если новая проверка показывает `is_registered=False`, а прошлая была `True`:
    - enqueue `send_wishlist_available_notice(user_id, domain)`
    - после успешной отправки — `DELETE FROM user_domains WHERE id=…` (одноразовость)
- При попытке `/wishlist <уже-free-домен>` бот всё равно добавит, и при первой же
  проверке пришлёт уведомление (так как `old.is_registered=True` будет ложным —
  старого состояния нет; см. ADR 026 — мы НЕ триггерим уведомление для первой
  проверки без old_data, чтобы избежать ложных алертов).

**Уведомление об освобождении:**
```
🎉 Домен example.com освободился!

Можете зарегистрировать через любого регистратора.
…
[📌 Начать отслеживать] [OK]
```

## Обработка плоского текста (не команда)

Если сообщение не команда и пользователь не в FSM:

**Если сообщение целиком похоже на домен:**
- Запускаем `/whois <domain>` логику
- Inline-кнопки: `👁 Следить` (если не отслеживается) или `🗑 Снять` (если да)

**Если сообщение содержит URL:**
- Извлечь host, проверить, валидный ли домен → как выше

**Иначе:**
- Игнорируем (или показываем подсказку `Используйте /help` — обсуждаем при реализации)

## SQL для выборки напоминаний об истечении

Псевдо-SQL для основной логики рассылки (вызывается раз в час планировщиком, отбирает пользователей, у которых сейчас локальный `notify_at_hour`):

```sql
WITH active_users AS (
    SELECT id, notify_days
    FROM users
    WHERE is_blocked = false
      AND EXTRACT(HOUR FROM (now() AT TIME ZONE timezone)) = notify_at_hour
)
SELECT ud.user_id,
       ud.domain,
       wc.expires_at,
       day_before
FROM user_domains ud
JOIN active_users u ON u.id = ud.user_id
JOIN whois_cache wc ON wc.domain = ud.domain
CROSS JOIN unnest(COALESCE(ud.notify_days, u.notify_days)) AS day_before
LEFT JOIN sent_notifications sn
  ON sn.user_id = ud.user_id
 AND sn.domain = ud.domain
 AND sn.notification_type = 'expiry'
 AND sn.days_before = day_before
 AND sn.expires_at = wc.expires_at
WHERE ud.notify_expiry = true
  AND wc.expires_at IS NOT NULL
  AND (wc.expires_at::date - (day_before || ' days')::interval)::date = current_date
  AND sn.id IS NULL;
```

Каждая выбранная строка → одна задача `send_reminder`.

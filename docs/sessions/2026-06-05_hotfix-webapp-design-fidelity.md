# 2026-06-05 — Hotfix: WebApp не соответствовал дизайну (архитектор, прямой коммит в main)

**Контекст.** Real-world тест v0.16.0 в Telegram: владелец сообщил, что
открывающийся WebApp «совершенно не соответствует дизайну». Диагностика и
фикс выполнены архитектором в одной сессии по явному решению владельца
(в обход обычного цикла task → PR — зафиксировано как осознанное исключение).

## Диагноз (4 независимые причины)

1. **CSS дизайна не был перенесён.** Дизайн `design/webapp/v1/app/` — это
   ~53 КБ CSS (colors_and_type.css + ds/styles.css + tg.css, 194 класса).
   В `webapp/src/styles/` было ~6,7 КБ, написанных с нуля: **42 из 55**
   классов, используемых в экранах (`tg-kpi`, `tg-ring`, `tg-cal-grid`,
   `tg-grp`, `tg-irow`, …), не имели ни одного CSS-правила; **5 переменных**
   (`--pv-fg-body`, `--pv-fg-muted`, `--pv-fg-subtle`, `--pv-divider`,
   `--pv-accent-soft`) использовались, но нигде не были определены.
2. **`telegram-web-app.js` не подключён в `index.html`** →
   `window.Telegram.WebApp` отсутствовал: не работали тема, BackButton,
   MainButton и initData-авторизация (все API-запросы шли без auth).
3. **Шрифты блокировались собственным CSP** (F7 аудита v0.16:
   `style-src 'self'`; font-src не разрешён) — `@import` с
   fonts.googleapis.com резался, Material Symbols не грузился, иконки
   рендерились голым текстом («language», «monitoring», …).
4. **`npm run build` не проходил** (tsc: неиспользуемые импорты) — билд
   фронта, судя по всему, ни разу не запускался при сдаче тасков 0067-0070.

## Фикс

- `webapp/src/styles/{tokens,ds,tg-chrome}.css` — вербатим-копии
  `colors_and_type.css`, `ds/styles.css`, `tg.css` (sed-перенос), минус
  Google-импорты и минус `.tg-viewport`/`.tg-phone` (обёртка «телефона»
  из прототипа). Порядок подключения — как в HTML прототипа.
- Шрифты самохостятся: `@fontsource/pt-sans` (400/700 + italic),
  `material-symbols` (rounded) — CSP остаётся строгим, офлайн-friendly
  (в духе ADR 035).
- `index.html`: подключён `https://telegram.org/js/telegram-web-app.js`
  (CSP уже разрешает telegram.org), viewport дополнен
  `maximum-scale=1.0, user-scalable=no` (как в прототипе).
- `App.tsx`: корень — `.tg-screen`, скролл-область — `.tg-body`
  (вместо inline-стилей); `Icon.tsx` добавляет класс `ms` (по нему
  tg.css задаёт контекстные размеры иконок).
- `ListScreen`/`DomainRow`: разметка приведена к канону дизайна
  (`.tg-search` как контейнер с иконкой, `.tg-chips`/`.tg-chip2` вместо
  выдуманных `.tg-filters`/`.tg-chip`, `.tg-drow-main`/`.tg-drow-right`
  вместо `.tg-drow-info`).
- Удалены остатки Vite-шаблона: `src/App.css`, `src/index.css` (лишнее
  звено импорта), `src/assets/{hero.png,react.svg,vite.svg}`.
- Починен tsc-билд (неиспользуемые импорты в 3 экранах).

## Верификация

- Дифф «классы, используемые в src» ↔ «классы, определённые в CSS»: **0 пропусков** (было 42).
- Диф переменных `--pv-*`: **0 неопределённых** (было 5).
- `npm run build` — зелёный (раньше падал на tsc).
- eslint: 47 ошибок до фикса → 43 после (остаток — pre-existing `any`-долг, скоуп не расширялся).

## Открытые вопросы / хвосты (кандидаты в таски)

1. **Demo-fallback пережил TASK-0082**: `ListScreen.load()` в `catch`
   подставляет `demo.ru` с `toast('Демо')`. Противоречит цели 0082
   (убрать demo-fallback, показать error-state). Также `App.tsx` рендерит
   `DomainScreen` с хардкодным `demoD` вместо загрузки по id.
2. **Material Symbols = 5,3 МБ woff2** (полный вариативный шрифт).
   Нужен сабсеттинг под фактический набор иконок (pyftsubset, liga).
3. **eslint webapp красный давно** (pre-existing 43 ошибки, в основном
   `no-explicit-any`) — фронт не покрыт CI-линтом?
4. **Процессный урок**: ни один из тасков 0067-0071 (включая аудит) не
   поймал, что фронт не собирается и не соответствует дизайну. В DoD
   фронтовых тасков нужно: `npm run build` обязателен + скриншот-сравнение
   с прототипом + анти-дрифт-проверка классов (диффы из «Верификации»
   можно оформить CI-скриптом).

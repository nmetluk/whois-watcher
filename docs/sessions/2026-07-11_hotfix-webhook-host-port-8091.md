# Hotfix: хостовый webhook-порт вынесен в WEBHOOK_HOST_PORT (8091)

**Дата:** 2026-07-11
**Ветка:** `hotfix/webhook-host-port-8091`
**Тип:** экстренный фикс инфраструктуры (prod down)
**Базовый коммит:** `652638e`

## Инцидент

На хосте-поллере (crea1) общеизвестный порт 8080 занял осиротевший `go run`
проекта nx0. `ww-bot` не мог опубликовать docker-порт (`127.0.0.1:8080:8080`)
и висел в краш-цикле ~месяц. Раньше и внутренний бинд бота, и хостовый publish
были завязаны на один `WEBHOOK_PORT=8080`.

## Изменение

Развели два порта:

- **Внутри контейнера** бот слушает `8080` (`WEBHOOK_PORT`); healthcheck
  контейнера — тоже `localhost:8080`. Не меняется.
- **На хосте** docker публикует `127.0.0.1:${WEBHOOK_HOST_PORT:-8091}:8080`.
  Новая переменная `WEBHOOK_HOST_PORT` (дефолт `8091`).

Прод переведён на 8091 вручную (nginx upstream + monitor) до коммита.

## Файлы

Базовый хотфикс (`652638e`):

- `docker-compose.yml` — publish-порт → `${WEBHOOK_HOST_PORT:-8091}`.
- `.env.example` — добавлена `WEBHOOK_HOST_PORT=8091` с комментарием.

Follow-through (ревью архитектора — закрытие дрейфа потребителей порта):

- `scripts/deploy.sh` — пост-деплойный HTTP health-check больше не хардкодит
  `8080`: читает реальный published-порт через `docker compose port bot 8080`
  (fallback `127.0.0.1:8091`). Без этого следующий `deploy.sh` падал бы на
  health-гейте (или бил бы в чужой процесс, занявший 8080).
- `docs/deployment.md` — nginx `proxy_pass` (webhook + `/health`) → `8091`;
  описание compose-маппинга и troubleshooting-заметка про конфликт порта
  приведены к `WEBHOOK_HOST_PORT`.
- `CHANGELOG.md` — запись в `[Unreleased] → Fixed`.

## Верификация

- `bash -n scripts/deploy.sh` — синтаксис OK.
- Ревью `git diff`: внутренний бинд и healthcheck контейнера остаются на 8080
  (не тронуты); наружу — только `WEBHOOK_HOST_PORT`.
- Grep по репо: хардкода хостового `8080` в потребителях не осталось
  (`deploy.sh`, `deployment.md`, `docker-compose.yml`).

## Анти-дрейф (урок)

Класс бага: поменяли значение (хостовый publish-порт), потребители отстали
(`deploy.sh` health-check, nginx-доки). Правило CLAUDE.md — «изменил X → grep
всех потребителей». В базовом хотфиксе поменяли только compose + `.env`, но
`deploy.sh` и доки не подтянули. Закрыто здесь; health-check теперь читает порт
из источника правды (`docker compose port`), а не дублирует литерал `8091`.

## Открытые вопросы

- Прод-nginx и monitor переведены на 8091 вручную. Стоит убедиться, что их
  боевые конфиги где-то версионируются — сейчас в репозитории есть только
  пример nginx в `docs/deployment.md`, а реальный конфиг живёт на хосте.

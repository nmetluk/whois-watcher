## Резюме

Операционный слой реализован качественно и **прямо закрывает пробел, из-за
которого недавно потеряли данные доменов**: появились ежечасные бекапы Postgres
с проверкой валидности и подтверждением в админ-канал. Также: ежечасный
ops-пульс, дневные графики (21:00 МСК, 06:00-текст сохранён) и аудит-лог для
разбора инцидентов. 🔴/🟠 находок нет. Вердикт — **GO** (тег v0.15.0 после
зелёного CI). 🟢 — рекомендации (офсайт/шифрование бекапов как следующее
упрочнение).

**Верификация:** локальный `pytest` в песочнице недоступен (нет Python 3.11);
проверено чтением + отчёты исполнителя + интеграц-тесты в CI. Перед тегом —
подтвердить зелёный CI и **пересборку образа с `postgresql-client-16`**.

## Безопасность

- **Бекап:** `pg_dump` через `create_subprocess_exec` (аргументы списком, **не
  shell** — нет инъекции); пароль только через env `PGPASSWORD`, **не в
  аргументах/логах** (логируется лишь путь/таймаут/исключение). ✅
- **Аудит-лог/ops-отчёты:** context аудита — `{task, domain, error}`, без
  `BOT_TOKEN`/контактов/заметок; ops-отчёт — только агрегаты (ADR 019). ✅
- **`audit()` best-effort** — обёрнут в try/except + вызовы в `with
  suppress(Exception)`; не ломает горячий путь и не «фонит» в прод. ✅
- **Findings:**
  - 🟢 **Локальные бекапы не шифрованы и содержат PII** (registrant-emails из
    WHOIS-кэша, заметки пользователей). Выбор владельца — «Postgres локально».
    Рекомендация: контроль доступа к тому/хосту; офсайт+шифрование — следующее
    упрочнение (особенно после недавнего инцидента: локальный том пережил бы
    потерю хоста не всегда). → TASK-0065 (опц.).

## Архитектура

- **`audit_log` отдельно** от `system_events` (инциденты 90д vs аналитика 30д). ✅
- **ARQ-конвенция:** все cron'ы в `_build_cron_jobs`; бекап пишет
  scheduler-контейнер; том `ww_backups` смонтирован на worker+scheduler. ✅
- **Единый alembic-head** (миграция `20260609_audit_log`, обратима). ✅
- **Findings:** нет (🟢 ниже — мелочи).

## Надёжность

- Бекап: ротация `sorted(reverse=True)[keep:]` — держит **новейшие 36**, удаляет
  старые; verify (`pg_restore --list` rc==0 + size); статус в `ops:last_backup`
  (TTL 2ч); never-raises. ✅
- Ежечасный отчёт: нет `ops:last_backup`/ok=False → «бекап FAILED», не крашится;
  no-op без admin-channel. ✅
- Графики: `matplotlib.use("Agg")` до pyplot (headless); пустые данные →
  placeholder (не падает); рендер через `to_thread`. ✅

## Производительность

- Бекап — async subprocess (не блокирует loop); графики — `to_thread`; cleanup
  по `created_at` (индекс). ✅

## Тесты / anti-drift

- Юнит со `spec`; миграция `audit_log` round-trip; интеграц-тесты ARQ
  (TASK-0052) переиспользуются для реальных прогонов. Полный прогон — по отчётам
  зелёный; подтвердить на CI.
- **Findings:**
  - 🟢 `getattr(settings, "backup_keep", 36)` — защитный getattr на Settings
    (не ORM, низкий риск); `backup_keep` объявлен в Settings → можно прямой
    доступ.
  - 🟢 `cleanup_old_audit_log` строит interval через f-string с `int`-настройкой
    (`audit_retention_days`) — не инъекция (int), но можно bind-параметром.

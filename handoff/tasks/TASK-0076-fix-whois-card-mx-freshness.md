# TASK-0076 — /whois: доставка MX/SSL/DNS по готовности (ADR 040)

> Тело самодостаточно. Перед стартом:
> `git checkout main && git pull --rebase origin main`, затем `claim`.
> 🔴 Прод-баг (фидбек #3: «после DNS должен быть MX с подробностями — не работает»).

## Корень проблемы (подтверждён по коду)

При первом `/whois` (`_send_whois_card`, `src/bot/handlers/whois.py`) карточка
собирается сразу, а SSL/DNS/email-кэши ещё пусты → показывается **pending-
плейсхолдер** «⏳ собираю…» (`format_pending_block`), а реальный MX/SSL/DNS
появляется только при **повторном** `/whois`. Карточка одноразовая, сама не
обновляется (авто-edit отложен в ADR 040). Для пользователя «MX не появляется».

## Цель

Когда при первом `/whois` заэнкьюены фоновые проверки (SSL/DNS/email-intel) и
карточка ушла с плейсхолдерами — **доставить обновлённую информацию** по их
готовности (без повторного `/whois`).

## Изменения по файлам (выбрать подход, зафиксировать в отчёте)

- **Вариант A (предпочт.):** авто-edit сообщения карточки — при отправке
  запомнить `chat_id`/`message_id`; задачи `check_email_intel`/`check_ssl`/
  `check_dns`, отработав, при наличии «pending-карточки» этого домена/юзера
  пересобирают и `bot.edit_message_text` карточку. Контекст хранить в Redis
  (`ops:whois_pending:<...>`), TTL короткий. Переиспользовать механизм доставки
  из TASK-0075.
- **Вариант B (проще):** досыл **отдельного компактного сообщения** «📧 MX/SSL/DNS
  готовы» с обновлёнными блоками, когда последняя из заэнкьюенных проверок
  завершилась.
- Не плодить лишних сообщений: досылать один раз, только если был плейсхолдер.

## Инварианты (защитить тестами)

- Первый `/whois` с пустыми кэшами → плейсхолдеры + контекст доставки сохранён.
- По завершении фоновых проверок → карточка/блоки обновляются (edit или досыл)
  ровно один раз.
- Повторный `/whois` (кэш свежий) → MX/SSL/DNS сразу, без доставки.

## Definition of Done

- [ ] MX (и SSL/DNS) появляются после первого `/whois` без ручного повтора
- [ ] **Полный `pytest` зелёный**; `ruff`/`black`/`mypy`
- [ ] Реальная проверка в Telegram
- [ ] Per-session отчёт; `handoff.py validate`; PR + зелёный CI

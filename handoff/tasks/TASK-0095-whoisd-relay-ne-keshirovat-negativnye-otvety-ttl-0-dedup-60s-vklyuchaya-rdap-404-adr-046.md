# TASK-0095 — whoisd/relay: негативные ответы не кешируются (ADR 046)

> Тело самодостаточно: исполнитель в новой сессии НЕ видел чат
> архитектора. Контекст — этот файл, `handoff/STATE.md`, репозиторий
> **nmetluk/whois-proxy** и отчёты TASK-0091/0093.
>
> **Перед стартом:** `git checkout main && git pull --rebase origin main`
> → `claim`. Работа в основном в репо **whois-proxy** + на хостах;
> в whois-watcher идёт только session-отчёт + статус таска.

## Цель

Ни прод-whoisd, ни VDS-relay не отдают «no data»-ответ из кэша старше
60 секунд. «Свободен» во всём пайплайне — всегда (почти) live; 60с —
не кэш ответа, а дедуп-защита TCI/реестров от бурстов повторных
проверок одного домена. Вместе с TASK-0094 (бот) закрывает повторный
инцидент: проверили свободный → зарегистрировали → бот лжёт «свободен».

## Контекст / корень

- TASK-0093 сократил TTL негативов до `RU_UPSTREAM_TTL_NEG=3600` /
  `CACHE_TTL_NEG=3600` (env в systemd-юнитах) на обоих хостах; в репо
  whois-proxy commit `2ae4442` — `NO_DATA_RE` + `is_no_data()` +
  `NO_DATA_TTL=600`. Окно лжи до 1 часа осталось — инцидент повторился.
- `NO_DATA_RE`-патч покрывает ветки `whois` / `ru_upstream`.
  **Ветка RDAP (gTLD): проверить, кешируется ли RDAP-404 как ok на
  TTL_OK=24h — если да, это самый длинный остаточный stale-free.**

## Изменения (репо whois-proxy + хосты)

- `server.py` (оба варианта: main/proxy и edge/relay):
  - негативный ответ (is_no_data / RDAP-404) кешируется максимум на 60с
    (дедуп), позитивный — как раньше (TTL_OK);
  - дедуп: повторный запрос того же домена в пределах 60с после
    негативного ответа отдаёт тот же ответ без похода в upstream
    (по сути NO_DATA_TTL=60, тем же механизмом кэша);
  - RDAP-ветка: 404 от RDAP → тот же no-data путь (ttl=60), а не TTL_OK.
- Конфиг: `NO_DATA_TTL` по умолчанию 60 (env-переопределяемый).
- Systemd-юниты (прод + VDS): убрать `RU_UPSTREAM_TTL_NEG=3600` /
  `CACHE_TTL_NEG=3600` (или выставить 60) — env не должен молча
  перебивать новый дефолт. daemon-reload + restart.
- Деплой на оба хоста из git (урок 0093: хостовые патчи — только
  версионированные).

## Инварианты (проверить руками, зафиксировать в отчёте)

- Негативный ответ: `ttl_remaining` никогда >60; два запроса свободного
  test-домена с интервалом >60с — оба идут в upstream (`cached:false`).
- Бурст: 10 запросов подряд одного свободного домена → 1 поход в
  upstream (дедуп работает, TCI не штормит).
- Позитивный ответ (yandex.ru) — по-прежнему cached, ttl ~24h.
- `ok=true` для легитимного no-data сохранить (бот различает free
  от ошибки; ADR 045 guard живёт на стороне бота).
